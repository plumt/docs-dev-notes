# 백엔드와 웹

앱 저장소에는 서버·웹 코드가 없습니다. 2026-10 에 Firebase 서버 코드와 웹을 별도 비공개 저장소로 분리했고,
앱 저장소는 Android 앱과 그 빌드·검증 도구만 담습니다.

| 저장소 | 담는 것 |
|--------|--------|
| 서버 저장소 | 앱별 Cloud Functions, 보안 규칙, Remote Config 기본값. 앱마다 디렉터리를 따로 두고 서로 import 하지 않습니다 |
| 웹 저장소 | 앱별 개인정보 처리방침·이용약관 페이지 |
| 관리 콘솔 저장소 | 통계, 수동 알림 발송, Remote Config 관리 |

## 앱과 서버의 계약

저장소가 나뉘면 "앱이 기대하는 함수·필드와 서버가 실제로 내보내는 것"이 같은 커밋에서 맞춰지지 않습니다.
그래서 계약을 다음처럼 다룹니다.

- 계약 정본은 서버 저장소에 두고, 앱 저장소에는 출처를 표기한 사본만 둡니다.
- 서버 저장소 체크아웃 위치를 환경변수로 알려 주면 앱 쪽 검사기가 사본과 정본을 대조합니다. 없으면 대조를 건너뜁니다.
- 새 앱을 만들 때 앱 스캐폴더가 서버·웹 저장소의 뼈대 생성 명령을 안내합니다.

## 서버 호출

- 모든 앱이 Firebase App Check 를 붙이고, 서버 호출에 App Check 토큰을 헤더로 실어 보냅니다(debug 는 디버그 공급자, 운영은 Play Integrity).
- 앱 업데이트 판정용 버전 API 는 Hosting CDN 캐시 뒤에서 호출해, 앱 시작마다 함수가 실행되지 않게 했습니다.
- 운영 푸시 발송은 사람만 합니다. 에이전트나 스크립트가 운영 토픽으로 보내지 않습니다.

## 배포

- Android 빌드·배포는 Jenkins 가 합니다. 파이프라인은 별도 저장소에 있고, 로컬 스크립트로 원격 트리거합니다. 자세한 내용은 [ci-cd](../../ci-cd/README.md) 를 봅니다.
- 서버와 웹은 각 저장소에서 사용자 승인 후에만 배포합니다.
