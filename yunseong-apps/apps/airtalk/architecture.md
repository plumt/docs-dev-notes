# AirTalk 아키텍처

모듈 목록은 [README.md](README.md) 를 본다. 여기서는 암호화·동기화·세션의 설계와 풀었던 문제만 다룬다.

## 계층과 경계

- `core:domain` 은 Android·Room·Firebase 를 모른다. 화면은 domain 계약만 보고 `core:data` 를 의존하지 않는다
- Firebase SDK 타입은 `core:remote` 밖으로 나가지 않는다. SDK 골격(오류 분류·callable·리스너·Storage)은 공용 firebase 모듈이 갖고, 여기엔 경로·DTO·도메인 오류 대응만 둔다
- 암호화 구현은 공용 `crypto-e2ee` 에 있고 앱은 `core:crypto` 에서 설정과 봉투 종류만 준다. 다른 모듈은 `javax.crypto`·Tink 를 직접 부르지 않는다
- 서버 호출 계약은 서버 저장소가 정본이고, 앱 저장소의 사본을 원격 모듈 테스트가 읽어 대조한다

## 종단간 암호화

- 방마다 대칭 방 키를 두고 메시지 본문과 그룹 이름을 그 키로 암호화한다
- 방 키는 멤버마다 그 사람의 공개키로 감싸 배포한다(공개키 암호 기반 키 교환). 개인키는 기기 Keystore 로 보호한 키셋에 있고 기기를 떠나지 않는다
- 멤버가 바뀌면 방 키 세대를 올려 다시 배포한다. 탈퇴한 멤버는 새 세대 배포에서 뺀다
- 암호문에 방·메시지·보낸이·키 세대를 인증 데이터로 묶는다. 서버가 암호문을 다른 방이나 다른 보낸이로 옮겨 붙이면 복호화가 실패한다
- 로컬 DB 는 SQLCipher 로 암호화하고, 저장된 방 키도 별도 금고 키로 한 번 더 감싼다
- 보장하지 않는 것도 명시했다: 메타데이터(누가·언제·어느 방), 잠금이 풀린 기기 탈취, 서버의 공개키 바꿔치기(지문 확인 UI 는 범위 밖)
- 봉투 형식의 바이트 호환은 독립 구현으로 만든 테스트 벡터가 고정한다

## 동기화

- 화면은 Room 만 구독한다. 네트워크 결과는 Room 에 쓴 뒤 화면으로 흐른다
- 정상 수신은 푸시로 끝낸다. 서버 읽기는 공백이 생겼을 때와 방을 열었을 때만 한다
- 로컬에 있는 키·프로필·메시지는 다시 받지 않는다. 없다는 결과도 잠시 기억해 같은 조회를 반복하지 않는다(`ttl-cache`)
- 쓰기는 모은다. 읽음 위치는 디바운스해 Realtime Database 에 쓰고, 같은 값은 쓰지 않는다
- Firestore 영속 캐시는 끈다. 같은 데이터를 Room 과 SDK 캐시 두 곳에 두지 않기 위해서다
- 발신은 멱등 ID 를 단 발신 큐(`outbox`)로 보낸다. 재시도해도 메시지가 두 번 생기지 않는다
- 서버 보존 기간 밖이라 받을 수 없는 구간은 다시 조회하지 않고 로컬 자리표시로 남긴다
- 2026-11 에 앱 안에 따로 짜 두었던 부재 캐시·트랜잭션 포트·재시도 간격을 공용 `ttl-cache`·`transaction`·`backoff` 모듈로 바꿨다

## 세션과 기기

- 한 계정 한 기기다. 로그인 때 이 기기를 활성 기기로 등록하고, 다른 기기가 활성이 되면 로컬 DB 와 신원 키를 지우고 로그인으로 보낸다
- 계정 데이터 쓰기는 세션 준비가 끝난 뒤에만 지나가는 관문 하나를 거치고, 계정이 바뀌면 계정 범위 캐시를 한 곳에서 비운다
- 키가 없거나 손상됐으면 확인 대화상자 없이 새 키를 만든다. 이전 대화는 "볼 수 없는 메시지" 로 남는다

## 풀었던 문제

| 문제 | 원인 | 해결 |
|---|---|---|
| 기기 이전 뒤 로그인은 되는데 대화를 하나도 못 읽음 | 키 설정 파일만 옮겨지고 Keystore 마스터 키는 옮겨지지 않았다 | 백업·기기 이전에서 DB 와 설정 영역을 통째로 제외했다. 대가로 이전 뒤 화면 설정은 기본값이 된다 |
| 새 기기가 푸시를 못 받음 | 밀려난 이전 기기가 늦게 푸시 토큰을 등록해 새 기기 토큰을 덮었다 | 활성 기기 확인을 통과한 뒤에만 토큰을 등록한다. 토큰 갱신 요청도 같은 확인을 거친다 |
| 콜드 스타트가 잠시 멈춤 | DB 키 복호화와 동기화 그래프가 메인 스레드에서 만들어졌다 | 동기화 진입점을 지연 주입으로 받아 IO 스레드에서 만든다 |
| 알림 하나를 누르면 같은 방이 여러 번 열림 | 알림 탭으로 생긴 두 번째 Activity 뒤에 깔린 인스턴스도 딥링크 큐를 소비했다 | 화면이 RESUMED 인 동안만 큐를 소비한다 |
| 탈퇴할 때 Google 권한 철회가 실패함 | 앱을 다시 띄운 뒤에는 SDK 가 로그인한 계정을 모른다 | 탈퇴 직전에 계정 정보로 직접 철회하고, 계정을 끝내 모르면 기기 세션만 지운다 |
| 탈퇴한 사용자를 어떻게 보여줄지 | 서버가 친구·방·글을 모두 다시 쓰면 비용이 크다 | 서버는 탈퇴 표식만 남기고, 앱이 표시 시점에 "탈퇴한 사용자" 로 바꾼다 |
