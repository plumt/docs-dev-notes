# Diding - 기능별 상세

## 시작 (`feature:splash`)

공용 스플래시 골격으로 버전을 확인한다. 확인에 실패하면 캐시가 있어도 진행을 막고 재시도를 안내한다. 업데이트가 필요하면 스토어 이동과 앱 종료만 고를 수 있다.

## 오늘 (`feature:home`)

오늘 해당하는 할 일 목록을 보여 주고 완료를 토글한다.

- 오늘 목록 조립은 도메인 유스케이스가 한다. 보관되지 않은 할 일과 그날 완료 기록을 합쳐 반복 판정으로 거른다
- 진행 수·달성률은 UI 상태의 파생값이며 화면에서 다시 세지 않는다
- 목록이 비면 진행 카드 없이 빈 상태 화면을 띄운다
- 자정이 지나면 새 기준 시각이 들어와 목록이 새 날짜로 바뀐다

## 관리 (`feature:management`)

반복 할 일을 추가·수정·보관한다.

| 요소 | 내용 |
|---|---|
| 목록 | 제목과 반복 라벨(매일 / 요일 나열 / 매월 N일)을 카드로 표시. 목록 끝에 네이티브 광고 |
| 시트 | 제목, 반복 칩(매일·매주·매월), 요일 선택기, 일자 선택, 알림 토글과 시각 선택 |
| 저장 조건 | 제목이 공백이 아니고 반복 규칙이 온전할 때만 버튼이 켜짐(매주는 요일 1개 이상) |
| 저장 후 | 시트를 닫고 입력을 기본값으로 되돌린 다음 알람 전체를 재예약 |

- 보관은 물리 삭제가 아니라 보관 표시로 처리한다
- 저장 중에는 버튼을 꺼 재진입을 막는다
- 정확 알람 권한이 없으면 "알림이 늦게 올 수 있다"는 안내와 권한 허용 버튼을 보인다

## 캘린더 (`feature:calendar`)

- 월별 달력에서 날짜마다 할 일 수행률을 색으로 그린다
- 월 범위, 칸 배치, 날짜별 달성률은 도메인 계산으로만 구한다. 화면에서 반복 판정과 집계를 다시 쓰지 않는다
- 수행률의 분모는 그날 해당하는 할 일이다. 홈 목록과 같은 판정 함수를 쓴다

## 설정 (`feature:setting`)

- 알림 마스터 스위치, 정확 알람 권한 안내, 앱 버전(새 버전이 있으면 업데이트 표시), 공지사항(N 배지), 광고 제거·구매 복원, 문의 메일, 처리방침·약관, 오픈소스 라이선스. 화면 뼈대는 공용 `SettingsScaffold`
- 알림 켜기: 권한 확인과 요청 -> 허용일 때만 설정 값을 올리고 알람 전체 예약. 거부면 토글을 내리고, 영구 거부면 앱 설정 이동 안내
- 알림 끄기: 설정 값을 내리고 알람 전체 취소
- 문의 메일 주소는 주입으로만 받는다(네이티브 설정 클래스는 앱마다 생성되어 이 모듈에서 보이지 않는다)

## 알람 (`core:alarm`)

| 구성 | 역할 |
|---|---|
| 스케줄러 구현 | 알람 포트의 전체 재예약·전체 취소. 정확 알람 호환 계층으로 one-shot 알람 등록 |
| 발화 리시버 | 발화 시 재검증 후 알림 발송, 다음 알람 재예약 |
| 재예약 경로 | 재부팅·앱 교체·정확 알람 권한 변경 뒤 알람을 복구한다. 재부팅·앱 교체는 공용 재예약 리시버에 이 앱의 재예약을 기여하는 방식이다 |

같은 할 일의 다음 알림은 같은 id 라 앞 알림을 덮는다. 알림을 탭하면 앱이 열린다(앱 진입 정보 포트 사용).

## 딥링크

탭 네 개(오늘·관리·캘린더·설정)로 바로 이동하는 경로 없는 링크만 받는다. 경로가 붙은 링크는 거부되고 쿼리는 버려진다.

## 테마

공용 Paper 디자인 시스템 위의 밝은 종이 톤 고정 테마다. accent 는 그린, 브랜드 값은 한 파일에 모여 있고 시스템 다크 설정은 읽지 않는다.

## 테스트

- 반복 판정·달성률은 `core:domain`, 다음 발화 시각 계산은 `core:alarm` 이 고정 시각(`TimeProvider`)으로 검증한다
- 앱 모듈은 딥링크 매핑, 바텀바 표시 규칙, 목적지 계약, 광고 있음/없음 스크린샷을 검증한다
- E2E: testTag 를 resource-id 로 노출해 셀렉터로 쓰는 스모크 시나리오(dev 플레이버)가 있다
- 스토어 스크린샷은 debug 전용 `core:demo-seed` 로 "몇 주 쓴 사용자" 데이터를 심어 찍는다
