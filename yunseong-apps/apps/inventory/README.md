# Inventory (견본 앱)

## Basic Information

- **App Name**: Inventory
- **Status**: 출시하지 않는 견본 앱. Play 업로드 플러그인을 붙이지 않고, 비출시 앱에 업로드 플러그인이 없는지 테스트가 확인한다
- **Min SDK / Target SDK**: 29 / 36
- **플레이버**: `dev`, `prod` (규약 플러그인이 만든다)

## 목적

아직 채택한 앱이 없는 공용 모듈("재고")을 한 앱에 전부 엮어, 실제 앱에 붙었을 때 컴파일과 Hilt 그래프가 닫히는지 빌드마다 확인한다. 지금 붙은 재고는 24개다(분석·백업·캘린더·검색·테마 모드·잠금·온보딩·코치마크·소셜 로그인·재시도 간격·TTL 캐시 등).

## 왜 만들었나

공용 모듈은 단위 테스트만으로는 앱에 합쳐졌을 때의 상태를 알 수 없다. Hilt 는 주입 요청이 닿는 바인딩만 검증하므로, 아무 앱도 쓰지 않는 모듈은 바인딩이 빠지거나 공개 API 가 바뀌어도 아무도 모른다. 쓰는 앱이 생길 때 처음 깨지는 일을 막으려고, 재고 전부를 상시 조립하는 앱을 따로 두었다.

## 구조

```
:apps:inventory              조립 (Application 이 탐침을 주입받는다)
 ├─ core:assembly            재고 모듈별 확인 지점과 앱이 줘야 할 바인딩
 ├─ core:demo-seed           촬영용 데이터 (debug 빌드에만)
 └─ feature:home             재고 목록·확인 결과, 화면 있는 모듈로 이동
```

- 재고 모듈이 앱에 요구하는 바인딩은 `core:assembly` 한 곳에 모은다
- 견본 앱은 채택 수 집계에서 빠진다. 그래서 견본 앱이 붙여도 재고는 재고로 남는다
- Firebase·광고·스토어 자산·서버 계약은 붙이지 않는다. 소셜 로그인 키는 더미 값이라 앱은 뜨지만 실제 로그인은 실패한다

## 검증 방식

모듈마다 세 방식 중 맞는 것을 쓴다.

| 방식 | 드러내는 것 |
|---|---|
| 주입 | Application 이 받는 탐침(`InventoryAssemblyProbe`)이 모듈의 공개 타입을 실제로 요청해, 바인딩 누락을 Hilt 컴파일 오류로 |
| 호출 | Hilt 가 없는 순수 모듈의 공개 API 를 불러, 시그니처 변경을 컴파일 오류로 |
| 화면 | 화면이 있는 모듈을 route 로 연결해, 내비게이션 연결을 컴파일로 |

새 재고 모듈은 앱 의존·assembly 의존·탐침 항목 세 곳에 한 줄씩 붙인다. 검사 스크립트가 재고 목록(채택 앱 0개 공용 모듈)과 세 곳을 대조해, 빠진 모듈과 빠진 곳을 알리고 실패한다. 실제 앱이 쓰기 시작해 재고에서 빠진 모듈은 탐침에 남아 있어도 실패로 보지 않는다.
