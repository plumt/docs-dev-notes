# FxRate 아키텍처

## 모듈 구성

앱 모듈은 조립만 둔다(진입점, 내비게이션, 딥링크, 포트 바인딩). 환율 도메인은 이 앱 전용이라 shared 가 아니라 앱 하위 모듈에 둔다.

```
:apps:fxrate
├── core:common       환산·환율판·변동 판정·입력 파싱·통화 카탈로그·표기·소스 계약 (Android 비의존)
├── core:database     Room(캐시·즐겨찾기·알림 규칙) + 기준 통화 DataStore
├── core:remote       서버 환율 문서 구독 → 캐시 저장
├── core:widget       Glance 위젯, 리시버·리소스 소유
├── core:demo-seed    스크린샷 촬영용 데이터 (debugImplementation)
├── feature:rates     환율 탭
├── feature:alerts    알림 탭
├── feature:settings  설정 탭
└── feature:splash    강제 업데이트 게이트
```

feature 모듈끼리는 의존하지 않는다. 화면 사이 이동(예: 환율 화면의 알림 버튼 → 알림 탭에 통화쌍 전달)은 콜백과 효과로 올라와 앱 모듈이 처리한다. 위젯이 core 모듈이라 공유 로직을 화면 모듈에 두면 core 가 feature 를 의존하게 되므로, 공유 로직은 `core:common` 에 둔다.

## 데이터 흐름

```
서버 스케줄 → 외부 환율 API → 서버 환율 문서(Firestore) → (앱) core:remote → Room 캐시 → 화면·위젯
```

- 화면과 위젯은 값을 Room 캐시에서만 읽는다. 캐시에 쓰는 길은 서버 문서 구독 하나다
- 앱이 외부 API 를 직접 부르지 않는 이유는 호출량이다. 호출이 사용자 수에 비례하면 소스의 무료 쿼터를 금방 넘고, 서버 한 곳이 폴링하면 사용자가 늘어도 호출량이 그대로다
- 구독은 환율 화면이 보이는 동안만 붙는다. 시작 탭 ViewModel 은 백그라운드에서도 살아 있어, ViewModel 수명에 묶으면 안 보일 때도 read 가 나간다
- 구독이 끊기면 공용 `backoff` 모듈의 간격으로 다시 붙는다
- 계약에 어긋난 문서는 일부만 캐시에 쓰지 않고 실패로 올린다

## 핵심 설계

### 환산 (core:common)
- `CrossRateCalculator` 는 `1 X = N Q` 한 방향만 다룬다. 방향을 표현할 수단이 하나뿐인 API 모양으로 반대 방향 오류를 막는다. 테스트가 한 방향으로 일관되면 통과해 버리므로 규율이 아니라 형태로 막는 것이다
- 원본 기준 통화는 인자로 받는다. 함수 안에 통화를 박으면 서버가 기준을 바꿀 때 조용히 틀린 값을 낸다
- 이 모듈이 틀리면 예외 없이 숫자만 조용히 틀리므로 JVM 유닛 테스트로 검증 가능해야 한다. 그래서 Android·Compose 의존을 늘리지 않는다. 변동 색을 `Color` 가 아닌 ARGB 상수로 둔 것도 이 때문이다(화면 `Color` 와 위젯 `ColorProvider` 는 공통 상위 타입이 없다)
- 서식과 변동 판정은 기기 로캘에 기대지 않는다
- `RateBoard` 가 화면과 위젯의 환산·변동량·줄 고르기를 하나로 맡고, 둘의 차이(기본 목록·최대 줄 수)는 인자로 받는다

### 저장소 (core:database)
- 캐시와 사용자 데이터(즐겨찾기·알림 규칙)를 한 DB 에 둔다. 나누면 Room 인스턴스가 둘이 되는 비용 대비 이득이 없고, 대가로 파괴적 마이그레이션을 쓸 수 없다
- 변동 기준점은 서버가 준 전일 종가다. 서버가 자주 쓰면 "직전 값" 변동은 몇 분짜리 변동이 되고, 통화마다 마지막 변경 시각이 달라 교차 환산 화살표가 실제 추세와 반대로 나올 수 있어서다. 기준점이 없는 통화만 로컬이 직전 값을 같은 행에 두되, 값이 달라졌을 때만 옮긴다
- 빈 스냅샷은 캐시를 지우지 않는다. 소스 장애 때 오프라인 화면이 비는 것을 막는다
- 시각을 소스가 밝힌 기준 시각과 받은 시각으로 나눈다. 하나만 두면 사용자에게 실제보다 신선해 보인다. 갱신 주기도 서버가 쓰는 소스에 따라 바뀌므로 저장한다
- 알림 재발동 준비 상태는 서버가 소유한다. 앱은 규칙을 저장할 때만 초기화한다

### 앱 조립
- 시작 목적지는 스플래시이고, 홈 이동이 알려지면 환율 탭으로 가면서 스플래시를 백스택에서 지운다. 탭은 환율 → 알림 → 설정
- 딥링크는 host → route 맵 하나에서 화이트리스트와 라우터를 파생한다. 검증은 공용 디스패처가 하고 라우터는 매핑만 한다
- 위젯은 `MainActivity` 를 직접 참조하지 않고 앱 실행 정보 포트를 EntryPoint 로 받는다. 직접 참조하면 core 가 앱을 거꾸로 의존한다
- 개발용 시드 바인딩은 소스셋으로 갈려 목 데이터 코드가 release 에 아예 없다. 촬영용 데이터(`core:demo-seed`)도 debug 의존이라 스토어 빌드에 섞일 수 없다
- 테마는 공용 Paper 디자인 시스템에 강조색만 얹고, 시스템 다크 설정을 따르지 않는다

## 서버

서버 코드는 별도 저장소에서 관리하고, 앱과 서버의 문서 계약은 앱 저장소에 사본을 둔다.

- **구현됨**: 서버 스케줄이 외부 소스를 폴링해 환율 문서를 쓰고, 앱이 그 문서를 구독한다
- **계획**: 서버 알림 평가와 푸시, 차트용 이력
- **문서 하나에 전 통화**: 통화별 문서로 쪼개면 리스너가 통화 수만큼 붙어 read 가 그만큼 늘어난다
- **보이는 변화만 쓰기**: 쓰기 한 번이 화면을 보는 모든 리스너의 read 가 된다. 화면 숫자가 바뀌지 않는 변화는 쓰지 않고, 기준 시각만 가끔 갱신해 데이터가 끊긴 것처럼 보이지 않게 한다
- **소스 체인**: 주 소스가 막히면 공개 라이선스 폴백으로 넘어간다. 오래된 값이 새 값을 덮지 않게, 기준 시각이 저장값보다 앞서지 않으면 쓰지 않는다
- **알림 평가는 서버 몫**: 앱이 평가하면 앱이 꺼져 있을 때 알림이 가지 않는다. 임계값 근처 진동으로 알림이 폭주하지 않도록 히스테리시스를 건다. 매번 규칙 전체를 읽지 않도록 통화쌍별 경계 요약으로 먼저 거른다
- **규칙 조작은 서버 함수로만**: 클라이언트 직접 쓰기를 막는다
