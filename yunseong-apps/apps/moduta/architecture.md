# Moduta 아키텍처

## 모듈 구성

앱 모듈은 조립만 맡는다. 진입점, 내비게이션, 딥링크, 키 공급이 전부다. 버스·지하철 도메인은 앱 레벨에 없고 각 `core` 모듈이 쥔다.

```
:apps:moduta
├── core:database          SQLCipher Room (버스 캐시, 즐겨찾기, 막차 알림 규칙)
├── core:seoul-bus         서울 버스 API → 도메인 (화면 없음, Compose 미의존)
├── core:seoul-subway      지하철 실시간·막차 → 도메인, 번들 노선도
├── core:last-call         막차 알림 규칙·발화 시각·예약
├── core:widget            Glance 홈 위젯 + 갱신 워커
├── core:demo-seed         촬영용 데이터 (debug 전용)
├── feature:bus-search     탭 1
├── feature:subway         탭 2 (홈·노선도·도착 시트·막차 알림 패널)
├── feature:nearby-station 탭 3 (위치 권한)
├── feature:air-quality    탭 4
├── feature:settings       탭 5 (더보기, 막차 알림 관리)
├── feature:bus-map        지도 + 정류장 상세 (바텀바 숨김)
└── feature:splash         버전 확인 게이트
```

같은 앱의 feature 끼리는 서로 의존하지 않고, 화면 사이 이동은 앱의 NavGraph 가 맡는다. 화면이 없는 데이터 모듈은 `core` 에 둔다.

## 내비게이션

| 목적지 | 바텀바 |
|---|---|
| 탭 다섯 (버스 검색이 시작) | 표시 |
| 버스 지도, 정류장 상세, 지하철 노선도, 막차 알림 관리 | 숨김 |

- 노선명·정류장명은 한글·공백·괄호가 들어가므로 한 번만 퍼센트 인코딩해 넘기고, 꺼내는 쪽은 다시 복호하지 않는다. 예전 인코딩 + 재복호 조합은 `%` 가 든 이름에서 크래시하고 `+` 를 공백으로 바꿨다
- 탭 이동은 공용 바텀바가 탭별 백스택을 저장·복원한다
- 바텀바 표시는 각 목적지 진입 때 바꾸고, 지도·노선도 같은 서브 목적지는 하단 패딩도 0 으로 둔다

## 딥링크

host 에서 route 로 가는 맵 하나가 단일 출처다. 화이트리스트와 라우터 매핑이 이 맵에서 파생되고, 두 host 집합이 같은지 단위 테스트가 확인한다. 예전에는 둘을 따로 적어 한쪽만 고치면 링크가 조용히 거부됐다. 경로 없는 host 형태만 받고 쿼리는 버리며, 서브 목적지로 가는 링크는 없다. 콜드 스타트 링크는 내비게이션보다 먼저 도착하므로 큐에 넣어 두고 배선 이펙트가 라우터를 붙인 뒤 소비한다. 홈 위젯도 이 맵에 있는 host 만 쓴다.

## 서울 버스 데이터 레이어 (core:seoul-bus)

API 서비스 → 원격 데이터 소스 → 저장소 → UseCase 로 얇게 겹친다. 호출은 서버 프록시를 거친다.

- **응답 판정**: 이 API 는 키 만료·한도 초과도 HTTP 200 으로 보내고 본문 헤더의 결과 코드로만 알린다. 그래서 2xx 도 본문 전에 결과 코드를 보고, 정상과 결과 없음이 아니면 전용 예외를 던진다
- **캐시**: 공용 OkHttp 캐시를 쓰되, 실시간 버스 위치와 정류소 도착 안내는 매번 네트워크를 탄다. 초 단위로 바뀌는 값이라 캐시가 곧 오답이기 때문이다
- **좌표**: 응답마다 경도·위도 필드 이름이 다르다. 숫자로 못 읽은 좌표는 모델에서 걸러낸다
- **실행**: 저장소는 콜드 `Flow` 를 돌려주고 IO 디스패처로 요청과 매핑을 옮긴다. 실패 처리는 화면 쪽 상태 변환이 맡는다

## 지하철과 막차 (core:seoul-subway, core:last-call)

- 실시간 위치를 번들 노선도의 역 사이에 배치한다. 방향은 응답의 상하행 값을 먼저 보고 종착역은 보조로 쓴다. 실제 응답 표본으로 배치 규칙을 시험한다
- 역 이름은 정규화한 뒤 비교한다. 여러 요청 중 일부가 실패해도 견디고 전부 실패할 때만 오류로 본다
- 막차는 자정이 아니라 새벽에 하루가 바뀌는 운행일 기준이다. 운행일 계산과 시각 표기를 공용 `service-day` 모듈로, 요일 반복 규칙에서 다음 발화일을 고르는 계산을 공용 `recurrence` 모듈로 옮겼다. 기존 구현과 같은 결과를 내는지 패리티 테스트로 확인했다
- 막차 알림은 정확 알람 권한이 없으면 비정확 알람으로 내려간다. 리시버·권한 선언은 모듈 매니페스트에 있어 의존만으로 병합되고, 부팅 뒤 재예약은 공용 알람 모듈이 맡는다
- 발화 때 막차를 다시 조회하고, 실패하면 캐시로 알리되 빈 결과로 캐시를 덮지 않는다. 다음 회차 예약은 실패와 무관하게 건다

## 홈 위젯 (core:widget)

- 그리기 단계에서 네트워크를 부르지 않는다. 조회는 워커·새로고침 수신기·구성 화면만 한다
- 위젯·리시버는 상태를 갖지 않고 의존성은 Hilt EntryPoint 로 꺼낸다
- 주기 갱신 조건은 정책 객체 한 곳에서 정하고 테스트로 묶는다. 위젯 시각은 "HH:mm 기준" 같은 절대 시각만 쓴다

## 화면 설계

- **bus-search**: `onIntent` 하나만 공개하는 MVI. 오류 문구는 상태가 아니라 1회성 효과로 보낸다(상태에 담으면 회전 때 스낵바가 다시 뜬다). 목록은 `LoadState`
- **nearby-station**: 권한 거부는 오류가 아니라 별도 권한 축으로 표현하고, 권한 축과 목록 축은 겹칠 수 있으므로 화면 상태 전체를 sealed 로 만들지 않는다. 진입 가드로 탭을 오갈 때마다 권한 팝업이 뜨는 것을 막는다
- **subway**: 폴링은 화면 생명주기 이펙트로만 켜고 끈다. 화면 코드는 시각을 읽지 않고 ViewModel 이 `TimeProvider` 로 찍는다
- **bus-map**: 갱신 루프를 ViewModel 이 아니라 화면의 `repeatOnLifecycle(STARTED)` 안에서 돌린다(ViewModel 무한 루프는 테스트를 멈춘다). 카카오맵 라벨 아이콘은 벡터를 Bitmap 으로 래스터화해 등록한다(벡터를 그대로 넘기면 마커가 안 보인다)
- **air-quality**: 에어코리아 호출·변환·등급 판정은 공용 모듈에 있고 이 모듈은 표시만 한다

## 로컬 저장소 (core:database)

SQLCipher 로 암호화한 Room DB 다. 생성은 공용 DB 팩토리로만 하며, Room 빌더를 직접 부르면 암호화가 빠져 평문 파일이 남는다. 파괴적 마이그레이션은 쓰지 않고 스키마를 바꾸면 버전과 `Migration` 을 함께 올린다. 즐겨찾기는 공용 `favorites` 포트의 구현이다.

## 키 공급과 빌드

- 설정 JSON → 빌드 플러그인이 암호화한 NDK 산출물 `NativeConfig` 로 굽고, 앱 모듈이 Qualifier 로 각 모듈에 내려준다. feature 모듈에는 `NativeConfig` 심볼이 없다
- 카카오맵 앱 키만 두 길로 나간다. SDK 초기화는 `NativeConfig` 값으로, 매니페스트 meta-data 는 플레이버별 placeholder 로 넣는다(SDK 가 매니페스트를 직접 읽어 NDK 만으로는 숨길 수 없다)
- `preBuildVerify` 가 필수 키, 운영 광고 ID, 딥링크 스킴 일치를 빌드 전에 검사한다
- 테마는 공용 `AppThemeHost` 에 앱 테마를 넘겨 조립한다. 밝은 Paper 테마에 브랜드 파랑 하나가 포인트다

## 테스트

앱 모듈 테스트는 딥링크 매핑·경로 인자 인코딩·DI·셸 구성을 본다. 하위 모듈은 각자 `src/test` 를 갖고, 공용 모듈로 바꾼 계산은 패리티 테스트로 묶었다. E2E 는 testTag 기반 콜드 스타트 스모크이고 저장소 공용 러너를 쓴다(dev 플레이버 고정).
