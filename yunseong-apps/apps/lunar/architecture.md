# Lunar - 아키텍처

## 모듈 구성과 경계

```
:apps:lunar                    앱 조립 (Application, MainActivity, di/, navigation/)
 ├─ core:common                달 그림·포맷·모델·알림 설정·테마
 ├─ core:demo-seed             촬영용 데이터 (debug 전용)
 ├─ feature:splash             시작 화면 (앱 NavGraph 가 직접 연결)
 ├─ feature:home               탭: 홈
 ├─ feature:calendar           탭: 달력
 ├─ feature:explore            탭: 달 탐구
 ├─ feature:sky                탭: 이달의 하늘
 ├─ feature:settings           탭: 설정
 └─ feature:notification       FCM 핸들러 + 알림함 화면
shared:*                       앱 셸, 내비게이션, Paper 디자인 시스템, 광고, Firebase 등
공개 SDK                        달 계산(net.plumt.astro), 권한(net.plumt.permission), 광고(net.plumt.ads)
```

- 앱 모듈은 Application·MainActivity 와 `di/`·`navigation/` 패키지만 가진다. 화면 코드가 앱 모듈에 들어오면 규약 가드가 구성 단계에서 빌드를 멈춘다.
- 의존 방향은 `feature -> core:common -> shared` 한쪽뿐이다. `core:common` 은 feature 를 역참조하지 않는다.
- 달 천문 계산은 앱이 아니라 공개 SDK [sdk-kotlin-astro](https://github.com/plumt/sdk-kotlin-astro) 에 있고, Hilt 제공은 `core:common` 이 맡는다.
- 각 feature 는 `convention.feature` 규약 플러그인으로 library·hilt·compose 설정과 공용 presentation·ui·디자인 시스템 의존을 받는다.
- `core:demo-seed` 는 `debugImplementation` 으로만 붙고 코드가 `src/debug` 에만 있어 운영 빌드에 실리지 않는다. 스토어 스크린샷을 같은 데이터로 다시 찍으려고 만들었다.

## 화면 소유와 내비게이션

| 화면 | 그래프 등록 주체 |
|---|---|
| 스플래시 | 앱 `NavGraph` 가 직접 연결하고 시작 목적지로 둔다 |
| 홈, 달력, 달 탐구, 하늘, 설정 | 각 feature 모듈이 `FeatureDestination` 을 `@IntoSet` 으로 자가등록 |
| 알림함 | 앱 `NavGraph` 가 직접 연결, 바텀바 숨김 |

부팅 뒤 어디로 갈지는 앱 정책이라 스플래시만 앱이 소유한다. 나머지는 feature 가 route 상수와 등록 순서를 정하고, 앱은 그 집합을 순서대로 펼 뿐이다. 앱이 아는 것은 route 상수와 탭 라벨·아이콘뿐이다.

## 앱 셸 조립 순서

1. 테마 - 공용 `AppThemeHost` 에 Midnight 팔레트와 달 그림 색을 얹는다. Material 색도 이 팔레트에서 파생되어 공용 다이얼로그도 같은 톤이다
2. 딥링크 배선 - 라우터 부착·해제와 큐 소비
3. 종료 확인 - 공용 가드가 뒤로 가기가 앱을 떠날 때만 팝업을 띄운다. 다른 탭의 뒤로 가기는 가로채지 않는다
4. `AppShell` - 바텀 슬롯에 배너 광고와 바텀바를 세로로 얹어 둘이 함께 나타나고 사라진다
5. `NavGraph` - 셸이 계산한 하단 여백만 받는다

## 딥링크

host -> route 매핑 하나가 정본이다. 화이트리스트는 이 맵의 키로 만들고 라우터는 이 맵 자체를 받는다. 두 곳을 따로 적던 시절 한쪽만 고쳐 조용히 어긋난 일이 있어 한 곳으로 합쳤다.

- 경로 없는 host 형태만 통과하고 쿼리는 버린다. 탭은 누구나 열 수 있고, 알림함은 자기 앱에서 온 링크만 받는다
- 콜드 스타트 링크는 내비게이션보다 먼저 도착하므로 큐(최근 1개)에 넣고 배선 이펙트가 소비한다

## 데이터 흐름

```
TimeProvider (지금 + 자정마다)  ->  ViewModel  ->  달 계산 SDK (Meeus)  ->  UiState  ->  Compose
```

- 홈은 계산 값을 먼저 내보내고, 이어서 관측 지점·월출·월몰과 날씨를 덧붙여 다시 내보낸다
- 시각은 항상 `TimeProvider` 로만 읽어 테스트에서 고정할 수 있고, 날짜 경계는 한국 시간으로 자른다
- 위상 시각과 이름은 홈·달력·하늘이 같은 계산 경로를 쓰고, 앱 모듈 테스트가 세 화면의 값이 같은지 확인한다
- 실패는 1회성 이벤트가 아니라 상태로 알린다. 실패는 그 화면을 보는 동안 계속 참인 사실이라서다
- 천문현상·단기예보는 공공데이터 키가 필요해 서버 프록시를 거친다. 앱은 App Check 토큰만 붙이고 키를 갖지 않는다

## 알림 파이프라인

```
FCM (data-only) -> 공용 FCM 서비스 -> 메시지 라우터 -> 달 이벤트 핸들러
   -> 알림 토글 확인 -> 로컬 알림 + 알림함 저장
```

- 서버가 달 이벤트를 data-only 로 보낸다. notification 페이로드를 붙이면 백그라운드에서 핸들러가 불리지 않는다
- 알림은 두 갈래(달의 위상 / 특별한 달)이고 갈래마다 토픽이 따로다. 토글 둘은 독립이며 기본값은 둘 다 꺼짐(opt-in)이다
- 토글은 토픽 구독과 핸들러 쪽에서 두 번 확인한다. 끄기는 저장이 먼저라 구독 해제가 실패해도 핸들러가 막는다
- 켜기는 반대로 토픽 구독이 성공해야 ON 을 저장한다. 실패하면 OFF 를 저장하고 안내를 보낸다
- 안내 문구는 상태 필드가 아니라 일회성 효과로 보낸다. 상태에 두면 회전 시 같은 토스트가 반복된다
- 알림 설정은 DataStore 에 둔다. 이 기능 전용이고 Flow 구독이 필요해서다

## 달 위상 그림

`MoonPhaseImage` 는 위상 값으로 Canvas 에 직접 그린다. 명암 경계를 타원 호로 만든 경로로 그리고, 신월·보름·반달 부근만 별도 모양으로 붙인다. 접근성 설명은 같은 위상 값으로 위상 이름을 만들어 넣는다.

## 빌드와 보안 구성

- **규약 플러그인**: 플레이버·서명·가드는 `convention.android.application` 이 만든다. 앱 `build.gradle.kts` 에서 플레이버·서명을 다시 선언하지 않는다
- **NativeConfig**: 설정 JSON 을 빌드 때 암호화된 C 소스로 만들어 NDK 로 빌드하고 JNI 로 복호화한다. 비밀 값이 소스나 리소스에 평문으로 남지 않는다
- **빌드 전 검증(`preBuildVerify`)**: prodRelease 의 테스트 광고 ID 검사, 딥링크 스킴 선언 검사, release 서명 검사. 소스에 광고 ID 리터럴이 있어도 빌드를 멈춘다
- **크래시 리포트**: crashlytics 모듈을 의존하면 공용 로거에 리포터가 꽂힌다. 릴리스에서 오류 로그가 버려져 딥링크·알림 경로 오류를 볼 수 없던 문제를 풀려고 붙였다

## 알려진 함정

- 조립 전용 의존(FCM 핸들러, 알림함 구현)은 앱 소스가 import 하지 않는다. 빼면 빌드는 통과해도 기능이 사라지거나 Hilt 컴파일이 멈춘다
- 시스템 바 스타일은 어두운 쪽으로 고정한다. 앱은 늘 밤하늘 테마인데 기본값은 기기 모드를 따라 라이트 모드에서 상태바 아이콘이 묻힌다
